# 邀请制账号与设备接入：开发规格

状态：implemented-candidate / release-gated。2026-09-22 用户已授权业务开发与隔离验证；本轮未提交、外部发布或生产切换。实现及验收差距见 [evidence.md](evidence.md)。
决策依据：[ADR 0002](../../adr/0002-hosted-invite-only-accounts.md)。术语以[领域词汇表](../../../CONTEXT.md)为准；本文将 Q1–Q31 转换为行为与验收，不重新解释已选选项。

## Problem Statement

现有接入要求用户传递服务器连接串并理解网关登录，无法由运营者按人发放、撤销权限。当前单活隧道及缺少归属校验的会话路由、广播不满足多用户开放条件；两端存在跳过 TLS 校验的实现。需要让外部测试用户安全地连接自己的电脑，且不破坏已有 DSH/Codex 能力。

## Solution

运营者通过独立管理后台发放账号访问密钥；用户在 Windows PC 输入密钥登录，Android 扫码或输入临时配对码，经 PC 确认后控制该电脑可用后端。首版每账号一台 PC、一部手机，但不同账号的电脑可同时在线。所有 Agent、工具和文件操作仍在各自 PC 上执行；只使用自研出站 WSS 隧道。

## User Stories

编号是任务和验收的追踪标识。括号内为访谈来源。

1. US01 作为运营者，我要统一托管并邀请制发放账号，让用户不用自建服务器或注册。（Q1–Q2）
2. US02 作为运营者，我要用独立管理员密钥进入网页后台，不与 PC/Android 凭据混用。（Q4、Q17）
3. US03 作为运营者，我要生成并查看完整用户密钥，添加可修改备注，知道发给了谁；备注不参与登录。（Q14、Q25）
4. US04 作为 PC 用户，我要只输入一把账号访问密钥登录，无需用户名或密码；每账号只有一把有效密钥且无自动到期。（Q6、Q11、Q18）
5. US05 作为手机用户，我要扫码或输入配对码并等待电脑确认，无需单独输入账号密码或 TOTP。（Q5）
6. US06 作为用户，我要未完成配对的凭证仅在配对页打开且电脑在线期间有效；关闭、断线、退出或配对成功即作废，最小化不算关闭。（Q8、Q12）
7. US07 作为用户，我要一次绑定使用该电脑已经启用的 DSH/Codex，不为每个后端重复绑定。（既有 Binding Scope）
8. US08 作为测试用户，我要自己的电脑和手机与其他用户同时在线，彼此看不到、也控制不了对方设备与会话。（Q3、Q10 及开放安全前提）
9. US09 作为 PC 用户，我要查看所绑定手机的名称、在线状态、最近连接时间，并改名或解绑。（Q9、Q13）
10. US10 作为更换手机的用户，我要先在 PC 解绑旧手机，再配对新手机；新手机不会自动挤掉旧手机。（Q9）
11. US11 作为更换电脑的用户，我要在新 PC 明确确认替换原 PC，旧 PC 断开、手机重新配对；不要求旧 PC 在线或管理员介入。（Q10）
12. US12 作为用户，我要正常关闭、重启和断网后恢复已有登录与配对，离线时不排队发送请求。（Q16、既有 Offline Control）
13. US13 作为手机用户，我要退出登录仍保留绑定名额；重新扫码/输入码并经 PC 确认即可恢复同一设备，不必先解绑。（Q27、Q30）
14. US14 作为 PC 用户，我要主动退出时停止远程使用但保留绑定；同一 PC 用原密钥重新登录后，未退出的手机自动恢复。（Q27、Q31）
15. US15 作为运营者，我要永久禁用账号且不能重新启用，需恢复使用时另发新账号。（Q26）
16. US16 作为运营者，我要重置密钥时替换为新账号，清除旧账号/设备登记与统计，旧凭据全部失效。（Q15 由 Q22 修订）
17. US17 作为运营者，我要删除密钥时同时删除账号和服务器端设备登记。（Q19）
18. US18 作为 PC 用户，我要远程权限被撤销时，本地 DSH/Codex 任务继续，不删除电脑文件和本地会话。（Q20）
19. US19 作为运营者，我只需每账号滚动近 24 小时手机成功提交请求总数；各后端合并，不统计其他使用指标、不查看会话正文。（Q21、Q23–Q24）
20. US20 作为现有用户，我要明确的升级提示，升级后按新流程重新接入一次，旧连接串不再能登录。（Q28）
21. US21 作为用户，我要客户端预设现有 IP 入口，不填写服务器地址，连接能验证真实服务器身份。（Q29 及安全前提）
22. US22 作为后续维护者，我要账号、设备、绑定、会话归属彼此独立，未来能放开同用户多手机/多电脑，而无需推翻身份模型。（Q3、Q10）
23. US23 作为手机用户，我要保留 DSH/Codex 分开的入口与现有聊天体验，Claude Code 保持空白占位，不恢复 Android 设备导航。（既有 UI 决定）
24. US24 作为测试者，我要在 Android Studio 模拟器上通过手动配对码完成端到端验证，不依赖真机开发者模式或摄像头。（既有验收约束）

## Implementation Decisions

### 已确认的边界

- 管理员密钥、账号访问密钥、临时配对凭证、设备授权分别属于不同权限用途，不能互相代用。密钥即账号是产品生命周期规则，不要求把原始秘密作为数据库主键。
- 账号是设备归属主体。授权后的路由上下文至少能区分账号、电脑、手机和后端；服务端从已验证身份推导归属，不信任客户端自报归属。
- HTTP 请求、WS 命令、推送、审批应答、隧道流、DSH launch token、目录服务、会话/模型缓存均须服从相同归属边界。不同账号即使使用相同后端会话 ID，也不得混淆。
- 单设备上限是首版策略，不是全服务单活连接。开发中需要重新设计当前单活隧道和固定全局适配器连接方式；不为每个用户向公网开放本地服务。
- 配对有“待确认→已授权”边界：仅持有配对码无访问权。成功兑换一次后失效；重复确认不得创建额外绑定。关闭/断线与确认竞态由服务器裁定，过期的配对页不能批准新授权。
- 手机退出后保留可识别原设备的登记关系，但已退出授权不能继续调用业务；恢复仍经 PC 确认。安装数据已丢失时不能仅凭相同设备名称认定为原设备，使用既定解绑/换设备流程。
- PC 退出停止其远程隧道和业务访问，但不撤销未退出手机的长期绑定；重新认证后才恢复。解绑、禁用、重置、删除和换电脑必须使相应旧会话/连接失效，不仅阻止下一次登录。
- Android 退出、重新绑定或更换归属时清理旧会话缓存、待审批与草稿所属状态，不能将账号 A 数据显示给 B；单纯断网仍允许按现有规则浏览有限缓存。
- 用户密钥允许后台受控回显，不能只存不可恢复摘要；需要可恢复密文、独立保管的保护密钥和访问控制。实现与测试使用合成凭据，真实密钥不得进入日志、URL、Git 或截图。后台不提供用户对话浏览接口。
- 禁用不是删除：保留禁用登记但无恢复操作；重置清除旧账号的登记和请求统计、创建新账号。删除清除账号关联登记和计数。必要操作记录仅保留最小脱敏信息，不成为旧账号秘密/对话的隐藏副本。
- 请求在电脑 Agent 确认受理后计入，任务后续失败不减计数；发送失败不计。时间按受理时刻，以服务器时间计算滚动窗口，不按手机时钟。模型调用、审批应答、心跳和列表刷新不是此指标。
- 不新增自动重发或排队机制。相同成功提交不得因响应重发而重复入账；用户再次主动发送且 Agent 再次受理属于另一次提交。无法确定是否受理时不得显示“保证未执行”或静默重试。
- IP 与端口是公开入口配置，不是账号凭据。TLS 身份校验覆盖两端 HTTPS/WSS 和后台浏览器访问；不得以全信任证书作为生产方案。证书信任材料的可信分发、续期与轮换是发布门槛。
- 生产迁移统一切换新接入协议；隔离开发环境可分步实现，但正式上线不能遗留旧共享密钥或旧浏览器登录作为旁路。

### 工程落地记录（不是新的产品选项）

实际接口、账号与设备标识、撤销、加密存储、配对限速以 product/README.md 跨端契约和 gateway/src/hosted 实现为准；运行与恢复步骤见 product/server/hosted-access-operations.md。保留现有 HTTP/WS、Adapter、隧道与客户端状态边界。

跨端 README 和各端 AGENTS 已更新候选版契约；生产登记明确仍运行旧版。运营后台受控显示用户密钥是专用例外，不解除普通日志、RPC 和推送的脱敏约束。

## Testing Decisions

已授权测试边界与完成要求（实际执行结果见 evidence.md）：

1. 主验收边界是实际 HTTP/WS 网关入口 + 两个隔离 PC 隧道客户端 + 可控假 Agent。复用现有 mock 冒烟与隧道端到端装配，真实覆盖认证、路由、推送和受理响应，不靠修改内部状态制造成功。
2. 配对/退出/吊销通过同一公开操作链验证。用独立临时数据目录和动态端口，时钟可控以测试滚动 24 小时；常规自动化不访问生产或付费模型。
3. PC 登录/确认/设备管理验证实际 IPC 和 UI 状态；Android Compose 测试验证绑定入口、错误恢复、两后端状态隔离；在独立测试 AVD 完成手动配对码真实联调，保留用户现有 AVD 数据。
4. 安全测试包含未认证 WS 接收零业务推送、跨账号伪造资源 ID/审批 ID/隧道目标失败，以及撤销后旧连接、重连和重放全部不能继续控制。
5. TLS 测试包含可信链/预置信任成功、错误 IP 身份/未知证书/过期证书拒绝、预定轮换路径成功；后台访问也不要求用户长期忽略证书告警。
6. 资源测试证明统计存储只保存必要计数数据、有窗口清理，心跳/流式消息不增加统计写入；给出观察到的存储量和内存，不宣称未经测量的性能数值。
7. 真实后端回归与 mock 验证分别报告：DSH 要验证会话/工作区、发送、流式、审批和提问；Codex 验证目前可用的读取、模型/权限与状态，并保留 Desktop writer 冲突提示及草稿，不能拿 mock 发送成功宣称已解决原桌面会话控制。
8. 每项任务提供失败用例、修复后结果、执行命令与环境、未运行项和原因。审查同时核对仓库规范与本规格。

## Acceptance Matrix

| 验收 ID | 操作/场景 | 必须可观察的结果 | 主任务 |
|---|---|---|---|
| AC01 | 管理员发密钥→PC 登录 | 无用户名密码；用户密钥不能进入后台，管理员密钥不能登录 PC | 02 |
| AC02 | 手机输码→PC 确认→发送 | 确认前零控制权，确认后仅目标电脑受理并返回状态 | 03 |
| AC03 | 关配对页、断线、成功后重放、并发确认 | 旧码拒绝且绑定名额不超限；最小化不使码失效 | 03 |
| AC04 | 两账号同时连接，互猜会话/目录/审批 ID | 各自成功，越权全拒绝，未认证及另一账号收不到推送 | 04 |
| AC05 | 正常关机/断网重连 | 登录和绑定保留；无离线请求队列 | 05 |
| AC06 | 手机退出→原手机重新配对 | 保留名额、旧授权无效，经 PC 确认恢复；新手机不能冒充 | 05 |
| AC07 | PC 退出→原 PC 原密钥重新登录 | 退出期间手机不可用，未退出手机随后自动恢复 | 05 |
| AC08 | 手机改名/解绑/更换；电脑更换取消/确认 | 名称和状态更新，旧设备失效；取消换电脑不影响原设备 | 05 |
| AC09 | 禁用/重置/删除，包括在线流与服务重启 | 吊销持久生效；禁用无恢复，重置新身份统计归零；本地任务继续 | 06 |
| AC10 | 成功/失败/重试/不同后端/窗口边界 | 只计实际受理，后端合计，24h 外消失，无正文或额外指标 | 07 |
| AC11 | 两端及后台访问可信/不可信 TLS 入口 | 可信成功，不可信失败，不泄露登录密钥；轮换兼容有证据 | 08 |
| AC12 | Android 模拟器、PC 包及隔离迁移演练 | 新流程完整，旧入口拒绝；原有 UI/后端能力无新增回归 | 09 |
| AC13 | 数据/配置/程序联合回退演练 | 可恢复一致版本且不意外恢复已撤销访问，不覆盖首页及其他反代 | 09 |

## Out of Scope

自主注册、计费、多设备数量开放、Claude Code 接入、手机独立账号密码、后台查看对话、额外分析指标、FRP 回退、服务器执行 Agent、扩大 Codex 当前底层能力，以及未经单独授权的生产切换或提交。候选构建属于本次已授权开发范围。

## Further Notes

- 产品规则由访谈收敛，开发已获授权；生产开放仍以验收矩阵和单独切换批准为前提。
- 当前工作树包含前序功能及其他工作的未提交变更，按基线登记保护。HEAD 不是完整功能基线。
- IP 证书具体实现、数据迁移与回退可行性必须由执行任务验证，不以旧文档关于证书供应商能力的断言作为依据。
- 若要求对外宣称“所有 Codex 桌面原会话可完整控制”，现有 writer 限制必须单独解决并验收，否则不得这样宣传本次认证改造。
