# ADR 0001：以 Codex app-server 承载远程 Codex 会话

状态：已接受（2026-09-21）

## 背景

DSH Link 要让手机操作运行在 Windows 电脑上的 Codex，并保持长任务、流式事件与权限控制。一次性 `codex exec --json` 适合脚本调用，但不能作为持续会话和手机审批交互的可靠基础。本机 Codex CLI 提供实验性的 `app-server` 接口。

## 决定

Codex 后端通过电脑本地的 `app-server` 接入。电脑端负责版本/能力检测、连接本地服务并持有 Codex 登录态；手机只经 DSH Link 网关发现和控制电脑已有的 Codex 桌面会话，或选择电脑已登记的 Agent 档案发起新会话。Codex 的服务端点不得暴露到公网。

Agent 档案由电脑固定定义；手机可在每次请求前选择一个档案，但不能编辑其权限规则。电脑端桌面会话是状态权威源，手机必须收到同一任务的状态变化。

电脑与手机对同一会话的操作必须双向同步。DSH Link 不能为了远程界面而替换 Codex 的原生并发与排队行为。

仅能创建独立新会话的本地包装器不满足本决定；桥接必须先验证能发现和接管现有桌面会话，才可在手机中声明支持该能力。

当已安装版本或协议不兼容时，手机必须明确显示 Codex 不可用。不得偷偷回退到无法安全传递审批的自动执行路径。

电脑端必须在运行时检测实际支持的会话、状态同步和权限能力；手机只能呈现已验证的能力，不能假设实验性接口的字段永久不变。

手机可经已有网关请求电脑选择本地任意目录来创建 Codex 会话，但目录枚举与路径校验必须留在电脑端。镜像工具事件必须先脱敏，不得把凭据同步到网关或手机。

## 后果

- 需要为实验性协议维护版本兼容性检测和契约测试。
- 电脑上陈旧或损坏的 `codex` 命令不能作为后端启动依据；必须识别可工作的 Codex 安装。
- 当前阶段只实施 Codex；Claude Code 接入留待 Codex 的桥接与手机镜像稳定后单独决策。
