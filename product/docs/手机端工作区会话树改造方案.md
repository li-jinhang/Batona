# 手机端「工作区 → 会话」树形结构整改方案

> 状态：**方案分析（暂不改代码）** · 日期 2026-09
> 目标：手机端能像电脑 Web UI 一样，按【工作区 → 会话】层级浏览/管理，支持工作区增删、会话新建/删除、展开折叠。

---

## 一、现状与问题

### 电脑（DSH Web UI）左侧
```
📁 工作区A
   ├─ 会话1
   ├─ 会话2
📁 工作区B
   └─ 会话3
```
- 工作区包含多个会话；可展开/折叠；支持工作区增删、会话新建/删除。

### 手机端当前
| Tab | 现状 | 问题 |
|---|---|---|
| 会话 | 顶部一个下拉框，显示**扁平的 session.list** 结果 | **没有工作区维度**，看不到"哪个会话属于哪个工作区"、无法按工作区浏览 |
| 工作区 | 列表只显示工作区名/路径/**会话数量** | **没展示每个工作区下的会话**，无法展开；缺工作区删除 |

**根因**：手机端的数据流是"会话列表"和"工作区列表"**割裂获取**，且 **UI 没有树形结构**、缺工作区/会话的增删操作。

---

## 二、DSH 的"工作区-会话"数据模型（已从源码核实）

- `workspace.list` → `{ items: WorkspaceView[], archivedSessionIds }`；
  - `WorkspaceView = { workspaceId, path, title, sessionIds: SessionId[], createdAt, updatedAt }`
  - **工作区下的会话就挂在 `sessionIds` 里**（有序数组）——这是关键关联字段。
- `session.list` → `SessionSummary[]`（sessionId/updatedAt/running/blank/cwd…），**本身不直接带工作区归属**，需通过 `WorkspaceView.sessionIds` 反查。
- 操作接口：
  - 工作区：`workspace.list/create/rename/delete/insertBefore/insertSessionBefore/archiveSession`
  - 会话：`session.create/fork/rename/…`（**无硬删除**）
  - 会话建立关联：`session.create` 可传 `workspaceId`（或将 `cwd` 指向工作区目录）即可归属到某工作区。

### 关键语义注意
| 用户预期 | DSH 实际 | 方案映射 |
|---|---|---|
| 删除工作区 | `workspace.delete`（只是取消注册，**目录/文件/会话保留**，会话变 ungrouped） | 直接映射 |
| 删除会话 | **DSH 无硬删除** | 用 `workspace.archiveSession`（归档，从分组表面隐藏）或界面提示"归档" |
| 新建会话到某工作区 | `session.create` 带 `workspaceId`/`cwd` | 网关传 `workspaceId` |

## 三、整改方案

### 3.1 网关层（`product/server/gateway`）——补 2 个能力

**① 新增 `workspace.tree` 方法**（一次拿全工作区+会话，减少轮询）
```
client-request  workspace.tree {}
server-response { items: [{
    workspace: { workspaceId, path, title, createdAt },
    sessions:  [ { sessionId, title?, state, updatedAt } ]   // 该工作区下的会话
}], archivedSessionIds }
```
- DshAdapter 实现：`workspace.list` 拿工作区 + `session.list` 拿会话元信息，**按 `WorkspaceView.sessionIds` join**；
- 会话元信息中的标题/状态：DSH `session.list` 有 `blank/running/cwd`，标题可用 `session.title` 事件或取 `cwd` 兜底。

**② 现有方法补齐参数/操作**
- `session.create` 增加可传 `workspaceId`（当前只传 `cwd`）；
- 新增转发 `workspace.delete`、`workspace.archiveSession`（归档会话）；
- （可选）`workspace.rename`。

### 3.2 App 端（`product/android`）——主页重构为树

**结构**（Compose）：
```
HomeScreen
 └─ 会话 Tab（原扁平下拉 → 树形）
     ├─ LazyColumn
     │   ├─ 工作区行 [▸/▾ 展开折叠]  📁 工作区名 (会话数)
     │   │    └─ 会话行（点击选中→聊天）
     │   └─ "未分组会话"（workspace 外的会话）
     ├─ 工具栏：新工作区 / 删除工作区 / 新建会话(当前工作区) / 归档会话
     └─ 聊天区（点会话进入）
```

- **数据**：主页 `workspace.tree` 一次性加载 → `worktree` state；
- **展开/折叠**：每工作区一个 `expanded` 布尔；
- **操作**：新工作区（输入路径→`workspace.create`）、删工作区（确认→`workspace.delete`）、新建会话（当前工作区→`session.create {workspaceId}`）、归档/删除会话（`workspace.archiveSession`）；
- 会话下拉框（现顶部）移除，改由树形选择。

### 3.3 UI 交互细节
- 工作区行点击 = 折叠/展开；长按 = 菜单（重命名/删除）；
- 会话行点击 = 进入聊天；长按 = 归档；
- "＋新会话"默认落入当前展开的工作区。

## 四、可行性评估

| 项 | 结论 |
|---|---|
| 网关改造 | 低难度：`workspace.tree` 是 `workspace.list` + `session.list` 的组装，join 逻辑简单；`session.create` 已支持 `cwd`，加 `workspaceId` 一行即可；`workspace.delete`/`archiveSession` 直接转发 |
| App 改造 | 中等：主页 UI 从"下拉+聊天"改为"树+聊天"两栏/可折叠；用 `workspace.tree` 替换会话/工作区两个割裂请求；操作按钮补充 |
| 数据准确性 | 依赖 DSH `WorkspaceView.sessionIds` 与 `session.list` 的 sessionId 一致（已核实一致） |
| 删除语义 | DSH 无会话硬删 → 用"归档"表达，避免误导用户"删没了" |

**预估改动量**：网关 ~30 行；App ~120 行（一个树形 Composable + 数据重塑）。

---

## 五、分步实施

1. **网关**：加 `workspace.tree` + `session.create` 支持 `workspaceId` + 转发 `workspace.delete/archiveSession`；
2. **App 数据层**：`GatewayClient` 加 `workspaceTree()` / `workspaceDelete()` / `archiveSession()`；AppState 加 `worktree`；
3. **App UI**：主页会话 Tab 改树形（折叠/展开、新工作区、删工作区、新会话、归档）；
4. 联调：电脑建工作区/会话 → 手机树形应一致；增删在两端同步。

## 七、结论

可行且改动可控：**核心是「网关加一个 `workspace.tree` 聚合接口」+「App 主页会话 Tab 从扁平列表改为树形」**。数据在 DSH 官方接口里已齐备（`WorkspaceView.sessionIds`），无需触达 DSH 内部。删除语义用"归档"替代 DSH 不存在的硬删除。
