## 1. 项目背景

用户在日常使用 **DeepSeek Harness（DSH）** 时，只能在笔记本前操作，无法离开电脑。用户希望：

- **随时随地用手机远程操控笔记本上的 DSH**（查看、对话、审批、管理会话与工作区）；
- 利用自己已有的 **带公网 IP 的服务器** 作为接入点；
- 未来扩展 **语音对话**（调用声学模型）与 **多 agent 后端**（Codex、Claude Code 等）；
- 无论自研还是采用开源组件，**架构必须保留上述扩展性**。

已核实的客观约束（来自 DSH 0.1.1-rc.2 源码，详见设计文档 §3）：
DSH 官方拒绝 `--host 0.0.0.0`；`trustedHosts` 不是认证；官方协议未版本化；无内置认证层。因此**必须自建接入网关**。

### 1.1 设计初衷（核心原则，任何时候不得违背）

> **DSH 本体是核心，DSH Link 是"桥"，不是"替代"。**

- **DSH 本体（笔记本上的 `dsh web`）必须在 PC 端完全不受影响地正常使用**：用户仍可像往常一样在浏览器里直接访问 `http://127.0.0.1:3080` 使用 DSH，其功能、配置、数据、体验**不被 DSH Link 以任何方式干扰、改写或降级**。
- **DSH Link 的初衷**：提供**手机直连电脑、使用 DSH 的另一种方式**（远程操控），与 PC 端 web 使用并行共存，二者互不冲突、互不依赖。
- **零修改 DSH 本体**：DSH Link 不补丁 DSH 源码、不改 DSH 配置、不在 DSH 侧注入额外逻辑。所有适配、认证、转发都在 **DSH Link 自己的接入网关 / PC 端 / 手机端**完成。
- **若某功能依赖修改 DSH 本体才能实现，则该项在 DSH 官方支持前不得强加**；宁可在网关做语义适配、延迟启用，也不破坏 DSH 本体可用性。
- **DSH Link 进程不常驻占用/无法访问时必须 graceful 降级**：DSH Link 或网关故障时，DSH 本体在 PC 端照常可用；DSH Link 只是"暂时不能用手机"而已，绝不影响本地操作。

> 这一原则决定了所有后续设计的取舍（尤其对 DSH 0.1.2 的 `/api` 浏览器认证：DSh Link 适配该机制，而**不是**去关闭/绕过 DSH 本体认证）。

## 2. 用户与使用场景

### 2.1 用户画像

| 角色 | 说明 | 设备 |
|---|---|---|
| 用户本人（唯一主要用户） | 开发者 / 重度 DSH 用户 | Android 手机（PWA 或原生 App）、笔记本（DSH 运行端） |
| 基础设施 | 用户自有的服务器 | 公网 IP、运行网关（**性能很低，仅承担转发**） |

### 2.2 使用场景（用户故事）

| # | 场景 | 故事 |
|---|---|---|
| US-01 | 出门在外 | 地铁上用手机打开应用，查看笔记本上 DSH 会话的进行状态，滑动审批工具调用，继续对话 |
| US-02 | 网络切换 | 手机从 WiFi 切到 5G（IP 变化），应用自动重连，会话上下文不丢、进度不丢 |
| US-03 | 语音交流 | 不方便打字时按住说话提问，听到语音回复（P2） |
| US-04 | 切换后端 | 同一应用内把会话后端从 DSH 切到 Codex / Claude Code（P1） |
| US-05 | 安全配置 | 首次登录扫码/验证码绑定设备；手机丢失后远程吊销该设备 |
| US-06 | 长任务 | 在手机上给 DSH 下达长任务后锁屏，随时回来看进度、必要时打断或审批 |
| US-07 | 新建工作区 | 在手机上浏览笔记本目录、新建文件夹、创建新工作区并立即开始会话 |

## 4. 功能需求（FR）

### 4.1 远程连接与传输（P0）

| ID | 需求 | 描述 | 验收标准 |
|---|---|---|---|
| FR-01 | 公网唯一入口 | 手机只能访问网关（公网服务器 443），DSH 不直接暴露公网 | 公网扫描 DSH 原端口无响应；仅 443 可达 |
| FR-02 | 出站隧道 | 笔记本在 NAT 后，主动出站连接网关即可被访问 | 笔记本无公网 IP / 无端口转发时手机仍可访问 |
| FR-03 | 全链路 TLS | 手机↔网关、网关↔DSH 全程加密 | 抓包无明文；证书有效 |
| FR-04 | 连接状态可见 | 手机端明确显示：在线 / 离线 / 重连中 | 状态切换 ≤1s 内反馈 |
| FR-05 | 断线自动重连 | 网络切换后自动重连并恢复会话上下文 | 模拟断网 30s 恢复后，会话消息、队列、审批状态完整 |

### 4.2 手机端操控 DSH（P0）

| ID | 需求 | 描述 | 验收标准 |
|---|---|---|---|
| FR-10 | 会话列表与历史 | 查看全部会话、标题、时间、状态 | 列表与笔记本端一致 |
| FR-11 | 发起对话 | 文本输入；图片上传（P1） | 消息送达并进入会话 |
| FR-12 | 流式输出 | 实时看到 assistant 增量、工具调用与结果卡片 | 输出逐字/逐块到达，tool/call 可视化 |
| FR-13 | 审批应答 | 工具调用审批：允许一次 / 拒绝 | 应答后笔记本端立即生效 |
| FR-14 | 提问应答 | 回答 agent 的提问（选项/文本） | 回答送达 agent |
| FR-15 | 取消/停止 | 停止当前回合、取消排队项 | 回合停止，状态回到 idle |
| FR-16 | 会话管理 | 创建新会话、恢复（含冷会话 resume）、重命名、删除 | 全部操作与笔记本端一致且持久化 |
| FR-17 | 模型选择 | 会话内查看/切换模型与推理档位 | 切换生效 |
| FR-18 | 多设备并发 | 手机与笔记本同时在线，操作互不冲突（走官方队列） | 双端并发操作无状态错乱 |
| FR-19 | 工作区管理 | 列出/新建/重命名/删除/归档工作区；远程浏览笔记本目录、新建文件夹以选定工作区路径 | 手机端可完成"浏览目录 → 新建文件夹 → 创建工作区 → 立即创建会话"全流程 |
| FR-20 | 会话安全边界 | 手机只能操作自己认证的设备与会话 | 无越权访问 |

### 4.3 认证与安全（P0）

| ID | 需求 | 描述 | 验收标准 |
|---|---|---|---|
| FR-21 | 登录认证 | 账号 + 密码 + TOTP 二次验证（MFA） | 无凭证不可访问；错误密码限速 |
| FR-22 | 设备注册与吊销 | 新设备需配对确认；已注册设备列表可远程吊销 | 吊销后该设备立即失效 |
| FR-23 | 登录限速与封禁 | 公网入口防暴力破解 | 连续失败触发延迟/封禁 |
| FR-24 | 审计日志 | 记录登录、设备、会话操作、审批行为 | 可追溯"谁在何时做了什么" |
| FR-25 | 最小暴露面 | DSH 进程只与网关/隧道通信 | DSH 仅监听 loopback |
| FR-26 | 会话安全属性 | Cookie 为 HttpOnly + SameSite=Strict，短期有效 | 安全属性审计通过 |

| ID | 需求 | 描述 | 验收标准 |
|---|---|---|---|

| FR-36 | 事件归一化 | 各后端事件统一为同一词汇（以 DSH 为准） | 手机端不感知后端差异 |

### 4.5 语音模态（P2）

| ID | 需求 | 描述 | 验收标准 |
|---|---|---|---|
| FR-41 | 语音输入 | 手机录音 → ASR 转文本进入会话 | 语音提问以文本消息进入会话 |
| FR-42 | 语音输出 | 回复文本 → TTS 语音播报 | 端到端延迟目标 < 2s（见 NFR-02） |

| FR-44 | 会话层文本化 | 语音只作为 I/O 模态，会话协议保持文本 | 语音开关不影响会话数据与事件流 |

## 5. 非功能需求（NFR）

| ID | 类别 | 需求 | 目标值 |
|---|---|---|---|
| NFR-01 | 可用性 | 网关 7×24 在线；网关故障不影响笔记本 DSH 本体 | 网关宕机时 DSH 本地继续可用 |
| NFR-02 | 性能 | 文本流式首块延迟（网络+网关开销）；语音端到端（P2） | 文本 ≤1s（4G）；语音 ≤2s |
| NFR-03 | 可靠性 | 断线自动恢复；会话不丢失 | 重连 ≤10s；DSH 侧会话数据为准，网关不复制数据 |
| NFR-04 | 安全性 | 凭据/密钥加密存储；不落明文日志 | 密钥存储审计通过 |
| NFR-05 | 兼容性 | DSH 0.1.x 升级兼容；手机端 Android + iOS 浏览器/PWA | 协议矩阵 + 回归测试基线（55 unary + 事件流） |
| NFR-06 | 可维护性 | 模块化、结构化日志、可观测性 | 每个模块独立可测 |
| NFR-07 | 服务器低配可行 | 网关在低性能服务器上可运行（不跑 LLM/agent/沙箱，仅转发） | 网关 CPU/内存占用处于低水位，转发吞吐满足单用户 |
| NFR-08 | 可扩展性 | 新增后端/模态不改核心 | 见 FR-51~54 验收 |

## 6. 约束与假设

### 6.1 技术约束（已核实）

- DSH 拒绝 `--host 0.0.0.0`；`trustedHosts` 只是防重绑栅栏，**不是认证**；
- DSH 官方协议（`/api` + Typert）**未版本化**，0.1.x 升级可能破坏适配器；
- 公网 IP 会持续被扫描，入口必须加固；
- 敏感操作（`host.openPath`、`settings.*`、`credentials.*`）官方仅限 loopback，远程必须由网关认证层兜底（经隧道以 loopback 权威访问可放行）。

### 6.2 假设

- **agent（LLM 调用、工具执行、沙箱）全部在笔记本端运行，服务器只做转发**（服务器性能很低）——这是既定架构（见设计文档 §4.4），非可选；
- 笔记本在使用时在线（若需 7×24，备选方案：DSH 跑在服务器，见设计文档 §4.4）；
- 服务器可运行 Node 网关 + Caddy（假设配置足够，低配可满足 NFR-07）；
- 手机端优先 Android，iOS 至少支持浏览器/PWA；
- 单人使用为主，但架构按"多设备并发"设计（FR-18）。

## 8. 总体验收标准（端到端）

1. **核心闭环**：手机在公网 4G 下完成"登录（MFA）→ 查看会话 → 发起对话 → 看到流式输出 → 审批工具调用 → 应答提问 → 断网重连恢复"，全程无笔记本端操作。
2. **工作区闭环**：手机端"浏览笔记本目录 → 新建文件夹 → 创建工作区 → 创建会话并对话"全流程可完成（FR-19 验收）。
3. **模型选择**：手机端查看模型目录、切换会话模型、配置 provider 均生效（FR-17 + FR-21~26 安全边界内）。
4. **安全**：未认证访问被拒；吊销设备立即失效；审计日志完整；DSH 不暴露公网。
5. **扩展**：演示"新增一个模拟后端适配器"与"更换语音模型"，手机端协议与网关核心零改动。
6. **兼容**：DSH 0.1.x 升级后按协议矩阵执行回归测试通过。

## 9b. 后续规划（Roadmap 待办）

> 以下为产品/运营层面后续要推进的待办，非当前 MVP 范围。每项给出目标与验收要点。

### R-1 多人同时使用

**目标**：把当前"单人单 DSH"的使用方式提升到**多人同时稳定使用**（FR-18 多设备并发的落地增强）。

| 项 | 说明 / 验收要点 |
|---|---|
| 并发会话隔离 | 多台设备/多人同时操作各自的会话，互不串扰（事件按会话归属正确扇出） |
| 多设备广播 | 同一会话被多端打开时，事件状态一致（FR-18 已按此设计，需实测并修并发边界） |
| 会话访问控制 | 用户只能看到/操作自己拥有的会话与设备（FR-20 安全边界，需强化） |
| 资源上限 | 防止单用户占满网关资源；限流/配额（结合 NFR-07 低配服务器） |
| 冲突处理 | 双端同时 prompt/审批的队列与状态同步（走 DSH 官方队列，需验证） |
| 账号体系 | 如需"多人各自账号"，评估多用户注册/密码/设备的存储与鉴权扩展 |

### R-2 服务器公开下载界面

**目标**：在服务器上布置一个**下载界面**，让用户能直接下载 **publish 的公开版本**（PC 安装包 / Android APK）。

| 项 | 说明 / 验收要点 |
|---|---|
| 发布产物 | 构建可分发产物：PC（NSIS 安装包 + 便携版，`npm run dist`）、Android（release APK 或 AAB） |
| 服务器下载页 | 服务器静态页展示各版本 + 下载链接（可用宝塔站点或网关 `webDir` 提供 `/download`） |
| 版本管理 | 明确版本号、更新日志、各端产物对应关系 |
| 下载安全 | 文件签名/哈希校验；下载页 HTTPS；不暴露源码/密钥 |
| 引导 | 下载页注明安装步骤、系统要求，跳转绑定说明 |

### R-3 日间模式与夜间模式切换

**目标**：手机端提供**日间/夜间主题切换**，提升在不同光线环境下的阅读体验。

| 项 | 说明 / 验收要点 |
|---|---|
| 主题切换入口 | 设置页提供「日间 / 夜间」切换开关（或跟随系统） |
| 主题一致性 | 全局配色（背景/卡片/文字/气泡/指示灯）随主题切换，无割裂 |
| 持久化 | 用户选择本地持久化（DataStore），重启后保持 |
| 可扩展 | 预留"跟随系统"（isSystemInDarkTheme）选项，方便后续接入 |

> 现状：App 目前为单一深色主题（`darkColorScheme`），需新增浅色配色方案并在 `App()`/根 Compose 处按状态切换 `MaterialTheme`。

### R-4 选择模型、切换模型

**目标**：完善手机端**模型选择与会话级切换**，与 DSH 电脑端的模型能力对齐。

| 项 | 说明 / 验收要点 |
|---|---|

## 10. 术语表

| 术语 | 含义 |
|---|---|
| DSH | DeepSeek Harness，运行在笔记本的 agent 工作台 |
| 网关 Gateway | 部署在公网服务器的自研接入层（认证 + 会话路由 + 适配器），**不运行 agent** |
| 适配器 Adapter | 统一对接某个后端 agent（DSH / Codex / Claude Code）的插件模块 |
| Typert / `/api` 协议 | DSH 官方 Host↔客户端 RPC 协议（详见设计文档 §3） |
| MFA | 多因素认证（账号密码 + TOTP 动态码） |
| 冷会话 resume | 恢复已持久化的历史会话（DSH 官方支持） |
| 工作区 Workspace | DSH 中一个目录 + 其下有序会话集合的实体（`workspace.*` 域） |
| ASR / TTS | 语音识别 / 语音合成（声学模型） |
