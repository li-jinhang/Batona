# 手机端「会话无标题」+「历史不显示」分析与修改方案

> 状态：**已解决** · 2026-09 · 下方的「根因 / 修改方案」为当时分析，**最终实际根因见本节**。
>
> 现象：
> 1. 工作区树的会话行显示**编号(会话 id)**，没有 DSH 的会话简介标题（如「C盘扫描权限查询」）；
> 2. 点会话进聊天，**聊天区没有历史消息**。

---

## ✅ 最终根因与修复（2026-09 已上服务器验证通过）

### 问题 2（历史不显示）—— 实际根因有两层

**(1) 网关读错了 DSH 响应键名（直接导致返回空）。**
DSH `session.history` 的响应是 `{ events: [{event,view}], hasMore, projections }` —— 键名叫 **`events`**，
而网关代码读的是 `r.value.entries ?? []`，永远读到 `undefined` → 返回空数组 → App 显示无历史。

**(2) 服务器 2GB 内存 + 网关无限堆 → OOM 崩溃。**
systemd 的 `ExecStart=/usr/bin/node dist/app.mjs` 没有 `--max-old-space-size`，V8 默认最大堆约 1GB。
DSH 一次 `session.history` 回放**上万条**原始流式事件（实测 19168 个、约 3.9MB，其中 20819 个是 `assistant/chunk` 增量片），
网关缓冲+聚合时内存暴涨 → **`Reached heap limit Allocation failed - JavaScript heap out of memory`** →
`systemd` 30s 自动重启。日志表现为"无 `[dsh-history]` 输出"、App 请求得不到响应历史为空。这与"代码已修复但不生效"的现象完全吻合。

### 修复内容

1. **网关 `dsh/adapter.ts` `history()`**：改读 **`events`** 键；`beforeSeq` 有值才传；
   DSH 回放原始流（`assistant/chunk` 增量片）不再直接丢给 App，新增 `aggregateHistory()` 聚合：
   - 忽略 `assistant/chunk` 流式增量（与完整消息重复）；
   - 保留 `user/message`、`assistant/message`、`tool/call`、`tool/result`；
   - `extractMessageText()` 只取 `assistant/message` 的 `type=text` 正文（丢弃 reasoning/tool-call）；
   - 默认只回放最近一段（`maxEvents` 上限），避免单次全量传输。
   - 实测：19168 个原始事件聚合为 **151 条**干净对话（49 assistant/message + 51 tool/call + 50 tool/result + 1 user/message），RSS 仅 70MB。

2. **`install.sh` `ensure_gateway_service()`**：systemd 加限堆：
   ```ini
   Environment=NODE_OPTIONS=--max-old-space-size=512
   ExecStart=/usr/bin/node --max-old-space-size=512 dist/app.mjs
   ```

### 部署要点（务必注意）

> ⚠️ **`install.sh` 不会随网关压缩包自动更新。**
> 必须**用解压出的新 `install.sh`** 执行 `--update`，否则沿用服务器旧 `install.sh` 只覆盖网关代码、
> **不会写入新 systemd 配置（限堆丢失）**，OOM 依旧复现。详见《部署指导.md》6.1「方案 A」。


## 问题 1：会话没有标题

### 根因
手机端会话行的 `title` 来源链：
```
工作区树 workspace.tree
  → sessions[].title
    → 网关 listSessions() 的 AgentSessionRef.title
      → DSH session.list 的 SessionSummary.title ???
```
- **DSH `session.list` 返回的 `SessionSummary` 不含 `title`**（已从源码核实：只有 `sessionId / updatedAt / running / blank / parentSessionId / cwd`）。
- 因此网关 `listSessions()` 拿到的 `title` 是 **undefined** → 工作区树组装 `sessions[].title = undefined` → App 显示兜底 `sNode.sessionId`（编号）。

### DSH 的标题在哪
DSH 会话标题（如「C盘扫描权限查询」）是 **`session/title` 事件**——DSH 根据对话内容自动生成，作为持久化会话事件存在会话日志里，**不在 session.list 里**。DSH 只有 `session.rename`（设置标题），**没有"读取标题"的独立接口**。

### 修改方案（按推荐顺序）

| 方案 | 做法 | 代价 | 说明 |
|---|---|---|---|
| **A. 确认 session.list 是否带 title** | 先实测 | 0 | 少量 DSH 版本可能在 list 里带 title；先验证，能省事 |
| **B. 标题事件缓存** | 网关 `DshAdapter` 在 downlink 收到 `session/title` 事件时缓存 `sessionTitle[sessionId]=title`；`workspaceTree` 组装时用它 | 网关小改 | 但网关冷启动时缓存是空的（历史标题事件早已过去），**必须配合 C 初始化拉取** |
| **C. 初始化拉取标题** | `workspaceTree` 时对每个会话调 DSH `session.history`，提取其中的 `session/title` 事件作标题 | 每会话 1 次请求 | 与 B 结合：冷启动用 C 拉一次，之后用 B 事件缓存增量更新 |
| D. 后端另加接口 | 网关新增"取所有会话标题"的 DSH 调用 | 需要 DSH 支持 | 依赖 DSH 是否提供，暂无 |

**推荐**：先做 **A**（很可能直接解），不行再用 **B + C**。
- 网关改动点：`dsh/adapter.ts`（加 `sessionTitle Map`、`mapEvent` 处理 session/title 缓存、`workspaceTree`/`listSessions` 用缓存填充 title）。
- **App 端基本不用改**：会话行已写成 `title ?: sessionId`，网关能给出 title 就自动显示。

## 问题 2：历史消息不显示

### 根因（最可能的几个，需实测确认）
手机点会话 → `resumeSession` → 网关 `session.resume` → 网关 `session.history`（转发 DSH `session.history`）→ 返回 `AgentEvent[]` → App 渲染。历史空白通常是下面之一：

1. **DSH `session.history` 返回为空/参数问题**：网关传 `{sessionId, beforeSeq, maxMessages}`，若 `maxMessages` 未设/或 `beforeSeq` 不对，DSH 可能回空；或该会话 DSH 侧**未 attach**，`history` 读不到持久化事件。
2. **事件 text 提取失败**：DSH history 的 `user/message`/`assistant/message` 事件正文在 `content: ContentBlock[]` 数组里，网关 `extractText` 可能没取到（若字段结构不同 → 文本为空 → 显示空行）。
3. **App `sessionHistory` 用的 id 不对**：App 用 `currentId`（网关 gatewaySession.id）调 `session.history`，网关路由到 backendSessionId —— 链路本身对，但要确认 resume 后 currentId 正确赋值。

### 排查（只读验证，帮我精确定位）
服务器执行（用真实 sessionId，可从 `session.list` 拿到）：

```bash
# ① 看 session.list 是否带 title（问题1 方案 A 的验证）
curl -s http://127.0.0.1:3080/api/session.list -X POST -H "Content-Type: application/json" \
  -d '{"type":"client-request","rpcId":"s","method":"session.list","payload":{}}'

# ② 看 session.history 对一个真实会话返回什么（问题2）
curl -s http://127.0.0.1:3080/api/session.history -X POST -H "Content-Type: application/json" \
  -d '{"type":"client-request","rpcId":"h","method":"session.history","payload":{"sessionId":"<上面拿到的某个sessionId>"}}'
```

**看②返回**：
- 有 `entries` 且含 `user/message`、`assistant/message` → 历史数据在，问题在网关提取/App 渲染；
- 返回空/无 entries → 参数或 attach 问题（试加 `"maxMessages":100`）。

### 修改方案
- **网关 `dsh/adapter.ts`**：
  - 修正 `history()` 的 DSH 调用参数（`maxMessages` 给足，`beforeSeq` 不传或正确）；
  - 修正 `extractText` 提取 DSH 消息正文（`content` 数组的 `text` 块、`assistant/chunk` 的 `delta`/`text`）。
- **App**：`sessionHistory` 逻辑已具备（`LaunchedEffect(currentId)`），确认 `resumeSession` 后 `currentId` 正确即可，一般无需改。
