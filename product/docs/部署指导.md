# DSH Link 三端部署指导文档

> 版本 v0.1 · 日期 2026-08 · 适用环境：**宝塔面板 Ubuntu 24（2核2G）服务器 + Windows 11 笔记本 + Android 手机**
> 目标：从零开始，把 DSH Link 三端全部部署好，手机能随时随地操控笔记本上的 DeepSeek Harness。
> 关联：[绑定协议](./绑定协议.md) · [产品 README](../README.md)

---

## 〇、总览：先看这张图再动手

```
       ① 服务器（约 40~60 分钟）              ② PC（约 20~30 分钟）            ③ 手机（约 30~60 分钟）
┌─────────────────────────────┐   ┌──────────────────────────────┐   ┌──────────────────────────┐
│ 宝塔终端跑一键安装脚本          │   │ 装 Node → 启动 DSH Link      │   │ Android Studio 构建 APK   │
│ 输出"连接串" dsh-gw://…        │   │ 粘贴连接串 → 自动起隧道        │   │ 扫码 → 自动填充 → TOTP    │
│ 宝塔：放行端口 + 反代 + 证书    │──▶│ 生成"手机配对二维码"          │──▶│ 会话/审批/工作区/模型      │
└─────────────────────────────┘   └──────────────────────────────┘   └──────────────────────────┘
```

**执行顺序**：先服务器 → 再 PC → 再手机。服务器装好拿到**连接串**是后面两端的前提。

**三端职责**（再次强调）：agent/LLM/工具执行全在 PC；服务器只转发；手机只管操控。

## 一、部署前准备（10 分钟）

### 1.1 需要准备的东西

| 项 | 说明 | 备注 |
|---|---|---|
| 服务器 SSH 登录 | 宝塔「终端」或 Xshell/FinalShell | root 权限 |
| 服务器公网 IP | 控制台/宝塔首页可见 | 记下来 |
| 一个强密码 | 网关管理员密码 | 12 位以上混合 |
| Android 手机 + 数据线 | 装 APK 用 | 开启"允许安装未知来源" |
| 电脑（本机） | Windows 11，已有 Node v24 + npm | 已确认可用 |
| Authenticator App | 手机上的 TOTP 验证器 | Google/Microsoft/1Password 均可 |

### 1.2 需要确认的环境事实

| 检查项 | 命令（本机 PowerShell） | 预期 |
|---|---|---|
| Node 版本 | `node --version` | v18+（本机 v24 ✅） |
| dsh 可用 | `Get-Command dsh` | 有路径（✅ 已确认） |
| DSH 是否在跑 | `Get-NetTCPConnection -LocalPort 3080 -State Listen` | 在跑更好（✅ 已确认在跑） |

> ⚠️ 无域名说明：Let's Encrypt 证书**必须要有域名**（HTTP-01 验证），纯公网 IP 无法签发。
> 本指导按"无域名 + 自签证书"展开；若你以后有了域名，把第 2.4 节的证书步骤换成宝塔"SSL → Let's Encrypt 一键签发"即可。

## 二、服务器端部署（宝塔 Ubuntu 24，2核2G）

### 2.1 接入代码（git clone）

服务器上的代码通过 git 从 Gitee **私有仓库**拉取，路径固定为
`/www/wwwroot/117.72.10.87/26-009DSHlink`（该目录即 git 工作区）。
首次接入（部署密钥 + clone）见 **[服务器部署-git.md §2](./服务器部署-git.md)**。

接入后确认（宝塔终端）：

```bash
cd /www/wwwroot/117.72.10.87/26-009DSHlink
ls product/server/install.sh          # 安装脚本
ls product/server/gateway/src         # 网关源码
bash product/server/deploy.sh --status   # 空跑看状态，不做任何改动
```

> 目录结构固定为仓库原样，不存在旧流程里"install.sh 在根目录还是 product/server/ 下"的
> 布局 A/B 之分——所有命令都不再需要 `--source`。

### 2.2 一键安装（10 分钟）

宝塔「终端」或 SSH 登录服务器（root），执行：

```bash
cd /www/wwwroot/117.72.10.87/26-009DSHlink

bash product/server/install.sh --install \
  --ip 117.72.10.87 --admin admin --password 你的强密码
```

**脚本会依次做**：
1. 检查/安装 Node.js（≥18，不足则装 NodeSource 24）
2. 安装 frps v0.68.0（反向隧道服务端），写入 `/etc/frp/frps.toml`（随机 token）
3. 部署网关代码到 `/opt/dsh-gateway/app`，`npm install` + 构建
4. 写配置 `/etc/dsh-gateway/config.json`（网关监听 `127.0.0.1:3090`，后端指向 `http://127.0.0.1:3080`）
5. 注册 systemd 服务 `dsh-gateway` 并启动，健康检查
6. **输出连接串**（重要，保存好）：
   ```
   dsh-gw://117.72.10.87?frpPort=7000&frpToken=xxxxxxxx&gwUser=admin&gwPass=xxxxxxxx&pair=xxxxxxxx
   ```

**验证**：
```bash
systemctl status dsh-gateway frps --no-pager | head -20   # 两个都 active (running)
curl http://127.0.0.1:3090/healthz                        # 预期 {"ok":true}
```

> 没传 `--password` 会自动生成随机密码并打印；`--ip` 不传会尝试自动探测公网 IP。

### 2.3 宝塔：端口放行（5 分钟，最重要）

**宝塔「安全」页 + 云厂商安全组，两层都要配：**

| 端口 | 是否放行 | 说明 |
|---|---|---|
| `7000/tcp` | ✅ 放行 | frp 控制端口，PC 软件连入 |
| `443/tcp` | ✅ 放行 | HTTPS 入口 |
| `80/tcp` | ✅ 放行（仅域名验证用，可不开） | Let's Encrypt 验证 |
| **`3080/tcp`** | ❌ **严禁放行** | DSH 隧道端口！放行=笔记本 DSH 裸奔公网（可执行任意命令） |
| `3090/tcp` | ❌ 不放行 | 网关只监听 127.0.0.1 |

> 云端如果还有安全组（防火墙），**同样要放 7000、443、拒绝 3080**。

### 2.4 宝塔：反向代理 + SSL（15 分钟）

**① 添加站点**：宝塔 → 网站 → 添加站点：
- 域名：无域名时先填 `dsh.local`（后面改成 IP 或用下面方式）

**② 反向代理**：进入该站点 → 反向代理 → 添加：
- 代理名称：`dsh-gateway`
- 目标 URL：`http://127.0.0.1:3090`
- 发送域名：留空

**③ 关键：确认 WebSocket Upgrade 头**：站点 → 配置文件，`location /` 内必须有：
```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```
没有就手动加（否则手机/PC 的 WebSocket 连不上，表现为"未连接"）。

**④ SSL 证书（无域名 → 自签）**：
```bash
# 服务器上一条命令生成自签证书（SAN 带 IP，手机可信任）
bash /www/wwwroot/117.72.10.87/26-009DSHlink/product/server/install.sh --selfsigned 117.72.10.87
```
然后在宝塔站点 → SSL → 其他证书，粘贴 `/etc/nginx/ssl/dsh-gateway.crt` 与
`/etc/nginx/ssl/dsh-gateway.key` 内容，保存。
（也可以直接用仓库 `deploy/server/nginx-dsh-gateway.conf` 替换站点 server 块，改 IP 与证书路径。）

**⑤ 验证 HTTPS**：
```bash
curl -k https://127.0.0.1/healthz      # 预期 {"ok":true}（-k 忽略自签证书）
```

### 2.5 安全核查（5 分钟）

```bash
bash /www/wwwroot/117.72.10.87/26-009DSHlink/product/server/install.sh --status
```
预期：两个服务 OK、healthz OK、**没有"3080 绑定 0.0.0.0"的严重告警**。

### 2.6 服务器端常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 安装脚本报 `curl: (22)` 下载 frp 失败 | 服务器访问 GitHub 受限 | 脚本顶部改 `FRP_VERSION` 对应的下载地址为镜像（如 ghproxy）；或手动下载 frp 放 `/usr/local/frp/frps` |
| 网关健康检查失败 | npm 安装/构建出错 | `journalctl -u dsh-gateway -n 50` 看日志 |
| 手机能开网页但 WS 连不上 | 反代缺 Upgrade 头 | 回 2.4 第③步补头 |
| 访问 443 超时 | 宝塔或云安全组没放行 | 两层都检查 |

## 三、PC 端部署（Windows 11）

### 3.1 环境准备

```powershell
node --version    # 预期 v18+（本机 v24 ✅）
npm --version
```

### 3.2 安装与首次启动

```powershell
cd D:\_Projects\26-009DSHplugin\product\pc
npm install          # 首次约 2-5 分钟（Electron 二进制 ~180MB，已用 npmmirror 镜像）
npm start            # 启动 DSH Link 窗口
```

预期：弹出 DSH Link 主窗口，显示「添加服务器」引导页。

> 打包成安装程序（可选，以后分发给别的电脑用）：`npm run dist`，产物在 `pc/dist/`（NSIS 安装包 + 便携版）。

### 3.3 绑定服务器

两种方式任选：
- **粘贴连接串**：把服务器 2.2 步输出的 `dsh-gw://…` 整段粘贴进输入框 → 点「解析并保存」；
- **摄像头扫码**：点「摄像头扫码」，对准服务器浏览器页（`http://IP:3090/pair.html`）的二维码或截图。

预期：提示"已绑定 xxx.xxx.xxx.xxx，开始启动服务…"，界面切到状态页。

### 3.4 一键启动服务

绑定后软件自动执行（无需手动操作）：
1. **探测 DSH**：检测 `127.0.0.1:3080` → 未运行则自动执行 `dsh --profile web --no-open` 拉起；
2. **启动 frpc 隧道**：自动下载 frpc.exe（首次，GitHub 约 10MB；慢可设环境变量 `DSHLINK_FRP_MIRROR` 后重启软件，或先跑 `npm run fetch-frpc`），写配置连服务器 7000 端口；
3. **守护**：frpc 崩溃自动重启；软件关闭窗口不退出（托盘常驻）。

**状态页四个灯的含义**：

| 灯 | 绿 | 红 |
|---|---|---|
| DSH | 笔记本 DSH 在运行 | 未运行/启动失败（看日志） |
| 隧道 frpc | 已连接服务器 | 断开（服务器 7000 没放行？连接串错？） |
| 网关 | 服务器 HTTPS 可达 | 反代/证书未就绪 |

> **开机自启**（可选）：设置页勾选"开机自启"（保持隧道常在线）。

### 3.5 生成手机配对二维码

状态页「手机配对」区会显示二维码（内容即连接串）。**手机 App 扫这个码**完成绑定。

### 3.6 PC 端常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志显示 frpc 下载失败 | GitHub 被墙/慢 | 设置 `DSHLINK_FRP_MIRROR=https://mirror.ghproxy.com/https://github.com` 重启；或 `npm run fetch-frpc` 预下载 |
| frpc 连不上服务器 | 7000 未放行 / token 不一致 | 服务器 `ss -ltn | grep 7000`；对比两端 token |
| 点一键启动 DSH 超时 | dsh 不在 PATH | 设置环境变量 `DSHLINK_DSH_CMD` 指向 dsh 完整路径（本机：`C:\Users\QH\AppData\Local\npm-cache\_npx\1e7f6d9597241db0\node_modules\.bin\dsh.cmd`） |
| 状态页网关红 | 证书/反代没配好 | 服务器 `curl -k https://127.0.0.1/healthz` 排查 |

## 四、手机端部署（Android）

### 4.1 构建 APK（30~60 分钟，首次含 Gradle 下载）

**前置**：电脑上安装 [Android Studio](https://developer.android.com/studio)（下载 ~1GB，安装 ~10 分钟）。

1. 打开 Android Studio → **Open** → 选择 `D:\_Projects\26-009DSHplugin\product\android` 文件夹；
2. 首次会提示下载 Gradle 与依赖（`com.android.application` 插件等），等待 **Sync** 完成（右下角无报错）；
   - 国内网络慢可配置镜像：`product/android/settings.gradle.kts` 里把 `google()` 前加阿里镜像 `maven { url = uri("https://maven.aliyun.com/repository/google") }`，`mavenCentral()` 前加 `maven { url = uri("https://maven.aliyun.com/repository/central") }`；
3. 菜单 **Build → Build Bundle(s) / APK(s) → Build APK(s)**；
4. 产物在 `product/android/app/build/outputs/apk/debug/app-debug.apk`。

### 4.2 安装到手机

- 数据线连接手机（开启 USB 调试），Android Studio 直接点 ▶ Run；
- 或把 `app-debug.apk` 传到手机（微信/网盘/数据线），点击安装；
- 手机需允许"安装未知来源应用"（首次会弹提示）。

### 4.3 首次绑定

打开 DSH Link App：
1. **扫码**：点「扫码」，对准 **PC 软件状态页的配对二维码**；
   （或手动粘贴连接串到输入框）
2. 自动解析 → 进入登录页，**账号密码已自动填充**（来自连接串）；
3. 点「登录」：
   - 首次：登录响应会返回 `otpauthUri`，App 会显示"请用 Authenticator 录入"→ 在手机 Authenticator 里录入 → 再次登录输入动态码；
   - 之后：直接输入动态码登录。

### 4.4 功能验证清单

| 功能 | 操作 | 预期 |
|---|---|---|
| 会话列表 | 进入主页 | 看到 PC 上的会话（含状态） |

### 4.5 手机端常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 扫码没反应/识别不了 | 二维码太小/摄像头权限未给 | 允许相机权限；让 PC 二维码大一点 |
| 登录提示无法连接服务器 | 服务器 443 未放行 / 证书问题 | 先手机浏览器访问 `https://IP/healthz`，能通再试 |

| 审批没反应 | frpc 隧道断了 | PC 软件日志看 frpc 状态，重启隧道 |

## 六、日常更新与维护（服务器高频更新场景）

### 6.1 服务器更新（改完网关代码后）

> ✅ **已改为 git 流程：本地 `git push` → 服务器 `dsh-deploy`。**
> 完整说明（含首次接入、部署密钥、回滚、排错）见 **[服务器部署-git.md](./服务器部署-git.md)**，本节只列日常操作。

**① 本机**（D:\_Projects\26-009DSHplugin）：
```powershell
# 1) 改 product/server/gateway/ 下的代码
# 2) 递增 product/server/gateway/package.json 的 version（如 0.1.30 → 0.1.31）
# 3) 提交推送（pre-push 钩子会自动跑 typecheck + build）
git add -A && git commit -m "网关：xxx" && git push
git tag v0.1.31 && git push --tags
```

**② 服务器**：
```bash
dsh-deploy
```

输出 `v0.1.30 → v0.1.31` 且校验项全为 `[OK]` 即部署成功；任一项不通过会**自动回滚**。

其他命令：`dsh-deploy --status`（看状态）· `dsh-deploy --rollback`（回滚）· `dsh-deploy --tag v0.1.30`（定版部署）

> **关于旧流程那段"旧 `install.sh` 会让限堆配置静默丢失"的警告**：
> 那是 tar 手工上传时代的固有问题——`install.sh`（部署逻辑）与 `gateway/`（业务代码）是
> **两条独立的上传路径**，沿用服务器上的旧 `install.sh` 跑 `--update`，就只是在旧逻辑上覆盖代码，
> 新版 systemd 配置不会写入（典型症状：2GB 机器拉大 history 时 `JavaScript heap out of memory` 崩溃重启）。
>
> 现在两者来自**同一个 commit**，且 `deploy.sh` 部署后会独立复核 `--max-old-space-size=512`，
> 该问题**结构性消失**——不再需要"方案 A"那套"必须用解压出来的新 install.sh"的绕法。

**更新保留**：`/etc/dsh-gateway`（连接串/配置）与 `/var/lib/dsh-gateway`（账号/设备数据）**不清空**，
所以 **PC 和手机无需重新绑定**。

**部署后验证**（`dsh-deploy` 已自动执行，手工复核用）：
```bash
curl -s http://127.0.0.1:3090/healthz                          # 预期 {"ok":true,"version":"0.1.31"}
cat /etc/systemd/system/dsh-gateway.service | grep old-space   # 预期 --max-old-space-size=512
journalctl -u dsh-gateway -n 5 | grep version                  # 预期 [gateway] version: 0.1.31
```

> ✅ 终端在执行 `dsh-deploy` 时，会打印 `版本 v0.1.30 → v0.1.31`。
> 把这个版本号发我即可确认服务器跑的是哪版；若与推送的版本不符，说明部署未生效（脚本会自行回滚并报错）。

> ✅ **DSH 0.1.2+ 的 launch token 由 PC 端自动上报，装完即通，无需手工配置。**
> DSH 0.1.2 的 `/api` 强制浏览器会话认证（无 API-key/关闭开关）。PC 端启动 DSH 时会从它的日志里抓
> `dsh web: http://127.0.0.1:3080/?token=…`，然后
> `POST https://<服务器>:<gwPort>/api/dsh/launch-token`（头 `x-dsh-agent-key` = 绑定串里的 `frpToken`）上报给网关；
> 网关热更新 token 并重建连接。**DSH 重启后自动恢复，不需要重新部署网关。**
>
> 网关侧对应配置项是 `agentKey`（`/etc/dsh-gateway/config.json`），`install.sh` 默认自动写入
> `server-info.json` 里的 `frpToken`。若要换成别的值：改 `"agentKey"` 后 `systemctl restart dsh-gateway`；
> **不配 `agentKey` 时该接口返回 404**（通道关闭，PC 上报会被拒）。
>
> 回退手段（DSH 不在 PC 上、无法自动上报时）：手工指定静态 token——
> ```bash
> # DSH 的 launch token 在它的启动日志里，形如 dsh_<base64>
> # 环境变量会透传给底层的 install.sh
> DSH_AUTH_TOKEN='<你的DSH-launch-token>' dsh-deploy
> ```
> 静态 token 每次 DSH 重启都会失效，仅作兜底；PC 端也可用环境变量 `DSHLINK_DSH_TOKEN=<token>` 手工指定（跳过自动抓取）。
>
> 同时看认证链路：PC 端日志出现 `launch token 已上报网关`，网关
> `journalctl -u dsh-gateway | grep -E "launch token 更新|\[dsh\] auth"` 出现
> `launch token 更新 → 重建连接` 与 `auth=launch-token ✓ cookie=set`
> （PC 软件界面「DSH（笔记本）」卡片下方也会显示 token 状态）。
