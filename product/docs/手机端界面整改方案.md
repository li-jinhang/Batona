# 手机端界面整改方案（参考网页版大模型 UI）

> 状态：**方案（待确认后实施）** · 2026-09
> 针对问题：
> 1. 「会话」Tab 把"工作区树 + 聊天区"**上下并排**，树占上半、下半空置，主次不分；
> 2. **点会话无反应**（没有切到聚焦的聊天界面，历史也没显示）；
> 3. 期望：点会话后，**会话/工作区信息在顶部持续显示**，**下方主要空间用于显示历史对话**——即大模型网页版（ChatGPT/Claude）的交互。

---

## 一、现状与根因

当前 `HomeScreen` 的「会话」Tab 是**一个页面里上下两块**：

```
Column
├─ 工具栏（新建会话/刷新/新工作区）
├─ LazyColumn (weight 1f)     ← 工作区树
└─ LazyColumn (weight 1.2f)   ← 聊天区（历史）
```

**问题**：
- 树和聊天**始终并排**：未选会话时聊天区是空的，下半白占；选了会话也只把历史灌进下半区，**没有"进入聊天界面"的视图切换**；
- 用户点会话 → 代码只是设置 `currentId` 并拉历史，但**页面结构没变**（还是树+聊天并排），且若历史/滚动没到位，看起来"无反应"。

---

## 二、目标与设计原则（参考网页版大模型）

| 原则 | 说明 |
|---|---|
| **两级视图** | 先看"会话列表"，点会话**进入独立的聊天主界面** |
| **顶部常驻信息栏** | 聊天界面顶部持续显示"当前工作区 / 会话标题"，返回后回到列表 |
| **对话流为主体** | 下方大块空间用于历史对话（user 右、assistant 左、工具卡片），可滚动 |
| **输入框固定底部** | 底部输入框常驻，对话流独立滚动 |
| **列表占满** | 未选会话时工作区树**占满整屏**，无空置 |

---

## 三、交互模型

```
[会话列表视图]                 [聊天主视图]
┌────────────────┐           ┌────────────────┐
│ 新建会话 刷新 新工作区│        │ ←  ﹢工作区/会话标题│  ← 顶部常驻信息栏
│ ─────────────  │           ├────────────────┤
│ ▸ 📁 工作区A    │           │  历史对话流       │
│   ├─ 会话1  ──点──▶ 进入聊天 │  user/assistant │
│   ├─ 会话2          │           │  tool 卡片       │  ← 主体（占满）
│ ▸ 📁 工作区B    │           │  流式输出        │
│  （占满）          │           ├────────────────┤
│  输入框(隐藏)      │           │ 输入框 + 发送    │  ← 底部固定
└────────────────┘           └────────────────┘
   ↑ 顶部"←"返回 → 回到列表视图
```

- **未选会话**（`currentId == null`）：显示**会话列表视图**（工作区树占满、工具栏在上；不显示输入框）；
- **已选会话**（`currentId != null`）：显示**聊天主视图**（顶部信息栏 + 主对话流 + 底部输入框）；
- **顶部「←」返回** → 清空 `currentId` → 回到列表视图。

## 四、详细布局

### 4.1 会话列表视图（未选会话）
```
顶部: [新建会话] [刷新] [新工作区]
      (点「新工作区」→ 展开路径输入行)
主体: LazyColumn（占满，**工作区/会话多时可上下滑动**）
        ▸ 📁 工作区A (N会话)       [+会话][删]
           ├─ 💬 会话标题  [状态]     [归档]   ← 点击 → 进入聊天
        ▸ 📁 工作区B ...
```

### 4.2 聊天主视图（已选会话）
```
顶部信息栏:  ←  |  📁 工作区名 · 💬 会话标题   [模型名可选]
主体: LazyColumn 对话流（占满，自动滚到底）
       user/message   右对齐浅蓝底
       assistant/message 左对齐
       assistant/chunk 流式追加
       tool/call / tool/result  工具卡片
       approval/requested / question/requested  ← 内嵌应答区（允许/拒绝/选项）
底部: [输入框…………] [发送]
```

## 五、状态与数据流

| 状态（HomeState） | 用途 |
|---|---|
| `currentId: String?` | **null=列表视图**；非空=聊天视图（该网关会话 id），同时是视图切换的开关 |
| `currentWsTitle: String?` | 顶部信息栏显示的「工作区名」（点会话时记录该会话所属工作区） |
| `currentTitle: String?` | 顶部信息栏显示的「会话标题」 |
| `lines: List<ChatLine>` | 对话流（历史 + 实时事件） |
| `worktree / expanded` | 会话列表（工作区树） |

- 点会话：`resumeSession(backend, backendSessionId)` → 网关 `session.resume` → 返回 gatewaySession → 设 `currentId`、`currentWsTitle`、`currentTitle` → 触发 `LaunchedEffect(currentId)` 拉历史 → 切到聊天视图；
- 返回按钮：`currentId = null` → 回列表视图（对话流不清，下次进入同一会话可复用/重拉）。

---

## 六、修复「点会话无反应」

实施时同时处理两点：
1. **视图切换**：用 `currentId == null` 驱动 `if/else`（列表视图 / 聊天视图）——点会话后`currentId`非空 → **整屏切换**到聊天，不再是"上下并排"；
2. **历史加载链路排查**：若点会话后聊天区仍无历史，可能是 `resumeSession` 返回空（网关 `session.resume` 失败）。排查/兜底方案：
   - 网关 `session.resume` 对未 attach 会话可能失败 → 兜底改为网关直接 `session.history`（App 可用 DSH 原生 `backendSessionId` 调历史）；
   - 或网关新增"按 backendSessionId 恢复/读历史"的健壮路径。

## 七、改动清单

**仅 `HomeScreen.kt`**（App 端，网关不改）：

| 改动 | 内容 |
|---|---|
| ChatTab 重构 | 拆成 **列表视图** + **聊天视图**，`currentId == null` 切换 |
| 顶部信息栏 | 聊天视图顶部 返回按钮 + 「📁 工作区 · 💬 会话标题」 |
| 布局调整 | 列表：树占满；聊天：信息栏 + 对话流(weight 1f) + 底部输入框(固定) |
| 状态 | `HomeState` 加 `currentWsTitle`；`onSelectSession` 记录工作区名 |
| 输入框 | 仅聊天视图显示（当前 bottomBar 常显 → 移到聊天视图内/条件显示） |

> 标题已能显示（上轮修复）✅；历史正文提取已修 ✅；本轮重点是把**布局改成两级视图**并修**点会话进入聊天**。

## 八、分步实施

1. 改 `HomeState`：加 `currentWsTitle`；
2. 重构 `ChatTab`：`if (currentId == null) 列表视图 else 聊天视图`；
3. 聊天视图：顶部信息栏（`←` + 工作区/会话名）+ 对话流 LazyColumn + 底部输入框；
4. 列表视图：工作区树占满（复用现有树渲染，去掉并排聊天区）；
5. `onSelectSession` 记录 `currentWsTitle`；点会话设 `currentId` → 自动切聊天；
6. 返回按钮清 `currentId`；
7. 构建 APK → 模拟器/真机验证。

---

## 九、验收标准

- 未选会话：工作区树**占满整屏**，无下半空置；**工作区/会话多时可上下滑动**；
- 点会话：**整屏切换**到聊天主界面，顶部显示「工作区 · 会话标题」，下方显示**历史对话**；
- 顶部信息栏在滚动/对话中**持续显示**；
- 底部输入框固定，发消息后流式输出进入对话流；
- 「←」返回回到列表视图；
- 对话流多时可上下滚动。

## 十、风险 / 待确认

- 顶部信息栏的「模型名」暂不显示（模型选择功能已有，展示待后续）。
